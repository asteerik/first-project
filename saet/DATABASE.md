# База данных проекта

Backend использует Django 5.2 и MySQL 8.0.16+. Таблицы создаются и изменяются миграциями Django; SQL-схему вручную редактировать не нужно.

## Сущности и связи

- `accounts_user` — единая учётная запись с уникальной почтой, хешированным паролем Django и ролью: соискатель, работодатель, модератор или администратор.
- `accounts_candidateprofile` — профиль соискателя (один к одному с пользователем). Видимость резюме по умолчанию закрытая.
- `accounts_organization` — организация и её владелец, контактные данные и статус проверки.
- `accounts_organizationmembership` — доступ нескольких пользователей к одной организации с ролью управляющего или специалиста по подбору; один и тот же пользователь не может быть добавлен в организацию дважды.
- `jobs_category` — категории вакансий.
- `jobs_vacancy` — вакансия организации, категория, автор, диапазон зарплаты и статус модерации.
- `jobs_application` — отклик соискателя на вакансию; повторный отклик на одну вакансию запрещён ограничением уникальности.
- `jobs_favorite` — избранные вакансии; повторное добавление запрещено ограничением уникальности.
- `jobs_complaint` — жалоба ровно на одну вакансию или организацию.
- `jobs_moderationlog` — журнал действий модераторов; записи нельзя изменять или удалять через админ-панель.

Внешние ключи настроены так, чтобы сохранять историю откликов и модерации. Для зависимых записей применяется защита от удаления (`PROTECT`), для избранного и профиля — каскадное удаление при удалении владельца/профиля. Ограничения на уровне БД предотвращают отрицательный диапазон зарплаты и жалобу без единственной цели.

## Локальный запуск

1. Установите Python 3.12+ и MySQL 8.0. Для Windows установите необходимые для `mysqlclient` компоненты согласно его документации.
2. Создайте пустую базу и отдельного пользователя MySQL (выполнить в MySQL как администратор):

   ```sql
   CREATE DATABASE church_jobs CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   CREATE USER 'church_jobs'@'localhost' IDENTIFIED BY 'replace-with-a-strong-password';
   GRANT ALL PRIVILEGES ON church_jobs.* TO 'church_jobs'@'localhost';
   ```

3. В PowerShell из корня проекта установите зависимости и задайте секреты окружения:

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   py -m pip install -r requirements.txt
   Copy-Item .env.example .env
   $env:DJANGO_SECRET_KEY = "replace-with-a-long-random-secret"
   $env:DB_PASSWORD = "replace-with-a-strong-password"
   ```

   Для локальной разработки можно установить `$env:DJANGO_DEBUG = "True"`. Секреты из `.env.example` — только примеры; не используйте их на опубликованном сайте.

4. Создайте таблицы и учётную запись администратора:

   ```powershell
   py manage.py migrate
   py manage.py createsuperuser
   py manage.py runserver
   ```

   Панель управления доступна по адресу `http://127.0.0.1:8000/admin/`.

### Локальный MySQL на этом компьютере

На этом компьютере настроен MySQL Server 8.4 с базой `church_jobs`, локальным пользователем приложения и отдельным портом `3307`. Настройки подключения и случайный Django-секрет сохранены в игнорируемом Git файле `.env`; пароль администратора MySQL зашифрован Windows DPAPI в профиле пользователя.

Каждый раз для запуска откройте два терминала PowerShell в корне проекта.

Если ранее в том же терминале задавали `$env:DB_ENGINE = "django.db.backends.sqlite3"` или `$env:DB_NAME = "dev.sqlite3"`, откройте новый терминал VS Code: переменные старого терминала имеют приоритет над `.env` и иначе подключат проект обратно к SQLite.

В первом запустите MySQL:

```powershell
.\scripts\start-mysql.ps1
```

Оставьте его работающим. Во втором запустите сайт:

```powershell
py manage.py migrate
py manage.py runserver
```

Админ-панель: `http://127.0.0.1:8000/admin/`. Учётная запись администратора из локальной SQLite-базы перенесена в MySQL вместе с хешем пароля. Файл `dev.sqlite3` сохранён как резерв исходной локальной базы и исключён из Git. Чтобы остановить сервер Django и MySQL, нажмите `Ctrl+C` в соответствующих терминалах.

Для временного тестирования без MySQL предусмотрены SQLite-настройки `config.test_settings`; основной локальный проект подключён к MySQL.

## API первой версии

Все API-адреса начинаются с `/api/`. После входа передавайте короткоживущий JWT в заголовке `Authorization: Bearer <access>`. Регистрация возвращает пару access/refresh токенов. Роли модератора и администратора нельзя выбрать при публичной регистрации.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/auth/register/` | Регистрация соискателя (`full_name`) или работодателя (`organization_name`) |
| POST | `/auth/login/` | Вход по email и паролю |
| POST | `/auth/token/refresh/` | Обновление пары токенов |
| POST | `/auth/logout/` | Отзыв принадлежащего пользователю refresh-токена |
| GET/PATCH | `/profile/` | Просмотр и изменение своего профиля соискателя |
| GET/POST | `/organizations/` | Список доступных работодателю организаций; создание организации |
| GET/PATCH | `/organizations/{id}/` | Просмотр или изменение организации её управляющим |
| GET/POST | `/organizations/{id}/members/` | Список участников или добавление работодателя (управляющий) |
| DELETE | `/organizations/{id}/members/{membership_id}/` | Удаление участника (управляющий) |
| GET | `/categories/` | Активные категории |
| GET/POST | `/vacancies/` | Поиск опубликованных вакансий или создание (работодатель) |
| GET/PATCH/DELETE | `/vacancies/{id}/` | Просмотр, изменение или закрытие собственной вакансии |
| POST | `/vacancies/{id}/close/` | Закрытие собственной вакансии |
| GET/POST | `/applications/` | Свои отклики / отклики на вакансии организации; отправка отклика |
| GET/PATCH | `/applications/{id}/` | Просмотр, отзыв или смена статуса доступного отклика |
| GET/POST | `/favorites/` | Список избранного или добавление вакансии |
| DELETE | `/favorites/{id}/` | Удаление своей записи из избранного |
| GET/POST | `/complaints/` | Жалобы; модераторы видят общую очередь |
| PATCH | `/complaints/{id}/moderate/` | Решение модератора по жалобе |
| GET | `/moderation/{organizations\|vacancies\|complaints}/` | Очередь проверки (параметр `status` необязателен) |
| POST | `/moderation/{organizations\|vacancies}/{id}/` | Решение модератора `approve` или `reject` |

Параметры поиска вакансий: `q`, `location`, `category` (slug), `employment_type`, `salary_min`, `salary_max`; для работодателя `mine=true` возвращает вакансии доступных ему организаций. Ответы списков постраничные (`page`, по умолчанию 20 записей).

Вакансия автоматически отправляется на проверку при создании и после редактирования; клиент не может самостоятельно выставить статус публикации. Публичный поиск показывает вакансии только проверенных организаций и вакансии, одобренные модератором. Владелец и участники организации видят её неопубликованные вакансии и отклики. Данные опыта и образования в отклике показываются работодателю только при видимости резюме `after_application` или `public`; закрытый профиль по умолчанию не раскрывает эти поля.

Ограничения API: анонимным клиентам назначено 100 запросов в час; авторизованным — 1000 запросов в час; вход ограничен 5 запросами в минуту, регистрация — 5 в час. Применяется JWT с 15-минутным access-токеном и refresh-токеном на 7 дней с ротацией и отзывом.

Проверки API выполняются на временной SQLite-базе, поэтому для них не требуется работающий сервер MySQL:

```powershell
$env:DJANGO_SECRET_KEY = "local-test-secret-at-least-32-characters"
py manage.py test jobs --settings=config.test_settings
```

## Резервное копирование и восстановление

Создавайте ежедневный дамп MySQL в защищённое хранилище вне сервера приложения и регулярно проверяйте восстановление. Не помещайте дампы в репозиторий. Пример команд для Windows:

```powershell
mysqldump --single-transaction --default-character-set=utf8mb4 -u church_jobs -p church_jobs > backup.sql
cmd /c "mysql -u church_jobs -p church_jobs < backup.sql"
```

Для резервной копии запустите в PowerShell `.\scripts\backup-database.ps1`. Скрипт читает параметры из `.env`, временно создаёт закрытый ACL файл MySQL вне папки проекта, удаляет его после выполнения и публикует дамп только при успешном завершении `mysqldump`. Настройте запуск скрипта ежедневно через Планировщик заданий Windows; копируйте дампы в защищённое хранилище вне рабочей машины. Для проверки восстановления используйте отдельную тестовую базу: создайте её, загрузите дамп командой выше, затем выполните `py manage.py migrate --check` с настройками тестового подключения.

Для реального запуска настройте TLS-сертификат и HTTPS на reverse proxy, задайте сильный `DJANGO_SECRET_KEY` и реальные `DJANGO_ALLOWED_HOSTS`, включите мониторинг и протестируйте восстановление резервной копии. Django перенаправляет HTTP на HTTPS и выставляет HSTS при `DJANGO_DEBUG=False`. Если TLS завершается на reverse proxy, задайте `DJANGO_TRUST_X_FORWARDED_PROTO=True` только когда прокси удаляет входящий `X-Forwarded-Proto` и сам устанавливает его корректно. В текущей версии загрузка файлов не реализована, поэтому файлы резюме пока не принимаются; перед её добавлением потребуются ограничения размера, проверка содержимого и безопасное хранилище. Текущие защиты API и прав доступа реализованы на сервере, но требуют проверки в целевом окружении перед публичным запуском.
