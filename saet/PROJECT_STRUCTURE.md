# Структура проекта «Ковчег Труда»

Проект собран как одно Django-приложение с общей папкой шаблонов. Это соответствует согласованному плану с Django templates: отдельный frontend-проект пока не нужен. Существующие backend-приложения `accounts` и `jobs` не переименовывайте — на них уже завязаны модели, API и миграции.

## Дерево проекта

```text
saet/
├── accounts/                      # Участник 3: аккаунты, роли и организации
│   ├── migrations/                # Миграции пользователей и организаций
│   ├── admin.py                   # Управление аккаунтами через админ-панель
│   ├── models.py                  # Пользователи, профили, организации и участники
│   ├── permissions.py             # Проверки доступа
│   ├── serializers.py             # Проверка и формат API-данных
│   ├── urls.py                    # Маршруты API аккаунтов
│   └── views.py                   # Регистрация, вход, профили, организации
├── config/                        # Общие настройки и запуск Django
│   ├── settings.py                # Настройки сайта, MySQL, API и шаблонов
│   ├── urls.py                    # Общие URL-маршруты
│   ├── test_settings.py           # Настройки автоматических тестов на SQLite
│   ├── asgi.py                    # ASGI-точка входа для публикации
│   └── wsgi.py                    # WSGI-точка входа для публикации
├── docs/                          # Документация для команды
│   └── PROJECT_STRUCTURE.md       # Этот файл: структура и распределение работы
├── jobs/                          # Участник 3: вакансии, отклики и модерация
│   ├── migrations/                # Миграции вакансий и связанных записей
│   ├── admin.py                   # Админ-панель вакансий, откликов и жалоб
│   ├── models.py                  # Категории, вакансии, отклики и избранное
│   ├── serializers.py             # Проверка и формат данных вакансий
│   ├── urls.py                    # Маршруты API вакансий и модерации
│   ├── views.py                   # Поиск, отклики и действия модератора
│   └── tests.py                   # Серверные тесты API и доступа
├── scripts/                       # Участник 3: локальные служебные скрипты
│   ├── backup-database.ps1        # Создание дампа MySQL
│   └── start-mysql.ps1            # Запуск локального MySQL
├── static/                        # Участники 1 и 2: общие ресурсы интерфейса
│   ├── css/                       # Стили сайта
│   ├── images/                    # Логотип и изображения
│   └── js/                        # Клиентские сценарии интерфейса
├── templates/                     # Участники 1 и 2: HTML-шаблоны Django
│   ├── accounts/                  # Формы входа, регистрации и кабинета
│   ├── jobs/                      # Каталог, карточка вакансии, форма работодателя
│   ├── pages/                     # Главная, о проекте, помощь и контакты
│   └── base.html                  # Общая шапка, навигация, подвал и блок контента
├── .env                           # Локальные секреты и подключение к MySQL; не передавать
├── .env.example                   # Пример настроек без настоящих секретов
├── .gitignore                     # Исключения для Git
├── DATABASE.md                    # Схема БД, API, запуск и резервные копии
├── manage.py                      # Команды Django
└── requirements.txt               # Python-зависимости проекта
```

Файл `[.env]` создаётся только на рабочем компьютере и не передаётся через Git. Каталоги `templates/` и `static/` пока являются заготовками: HTML-страницы и дизайн в них ещё нужно добавить. Загрузка файлов пользователей не реализована, поэтому каталога `media/` пока нет.

## Кто что делает

### Участник 1 — исследование и дизайн

- Описывает пользовательские сценарии, поля форм и тексты интерфейса.
- Подготавливает макеты в Figma и правила стиля.
- Передаёт логотип и утверждённые изображения участнику 2 для `static/images/`.
- Согласует названия страниц и элементов с участником 2.
- Не меняет модели базы данных и серверные права доступа.

### Участник 2 — интерфейс

- Создаёт общий `templates/base.html` с шапкой, навигацией, блоком `{% block content %}` и подвалом.
- Добавляет страницы в `templates/pages/`, `templates/jobs/` и `templates/accounts/`.
- Реализует стили в `static/css/`, JavaScript — в `static/js/`, изображения размещает в `static/images/`.
- Подключает формы и страницы к существующему API по маршрутам из `DATABASE.md`.
- Проверяет мобильную версию, состояния загрузки и ошибки, доступность интерфейса.
- Не меняет схему БД без согласования с участником 3.

### Участник 3 — сервер, база данных и безопасность

- Развивает модели и миграции в `accounts/` и `jobs/`.
- Реализует API, проверку данных и доступов, работу модерации и тесты.
- Настраивает MySQL, секреты окружения, безопасность публикации и резервное копирование.
- Согласует с участником 2 форматы API и нужные поля.
- Проверяет изменения командами из раздела «Проверки» ниже.

## Правила совместной работы

1. Сначала согласуйте макет, страницу и необходимые данные между участниками.
2. Участник 1 передаёт макет и тексты; участник 2 создаёт соответствующий шаблон и элементы интерфейса.
3. Участник 2 использует существующие API-маршруты из `DATABASE.md`; если нужен новый маршрут или поле, сначала согласует это с участником 3.
4. Участник 3 меняет модели только вместе с миграцией и проверкой тестов.
5. Не делайте параллельно несовместимые переименования приложений, файлов или URL.
6. Не помещайте `.env`, пароли, дампы БД и пользовательские данные в Git или общий чат.

## Полезные команды

Запустить сервер после старта локального MySQL:

```powershell
py manage.py runserver
```

Проверить API, Django и миграции:

```powershell
py manage.py test jobs --settings=config.test_settings
py manage.py check
py manage.py makemigrations --check --dry-run
```

Создать миграцию после согласованного изменения модели:

```powershell
py manage.py makemigrations
py manage.py migrate
```

Подробнее о MySQL и серверных API см. в [DATABASE.md](./DATABASE.md).
